Host: aarch64, Python 3.9.25. Both sides run under the fake clock and the fake control
plane: the script through its self-test's classes, the tool through its Rust cases with
HOST_STOP_KEEP set, which copies each case's evidence directory and printed lines.

  python3 -I driver.py PY_DIR   (from the top of the checkout)
  HOST_STOP_KEEP=RS_DIR CARGO_PROFILE_DEV_OPT_LEVEL=1 \
    CARGO_PROFILE_DEV_DEBUG=line-tables-only cargo test -p kestrike-tools --test tools -- \
    host_stop_controller::restore::restore_writes_restoration_once \
    host_stop_controller::restore::after_an_abort_restore_needs \
    host_stop_controller::restore::a_restoration_reaches
  diff -r PY_DIR/<case> RS_DIR/<case>; diff PY_DIR/<case>.lines RS_DIR/<case>.lines

driver.py loads scripts/test-host-stop-controller.py, runs the self-test cases
test_restore_writes_restoration_once_the_target_runs_with_both_checks_ok,
test_after_an_abort_restore_needs_the_reviewed_record_of_that_abort and
test_a_restoration_reaches_a_stopped_report_dated_after_the_abort_mark, and after the first
restore that exits 0 in each it copies the evidence directory and the lines printed so far.

After a clean run (restore-clean): the trees and the lines are equal. restoration.json:

{
 "instance": "i-h1",
 "reviewed_sha256": null,
 "state": "running",
 "time": 151.2
}

After a reviewed abort, the guardrail abort with its abort mark dated at the stop
(restore-reaches): the trees and the lines are equal. restoration.json:

{
 "instance": "i-h1",
 "reviewed_sha256": "68286e88ad3be34e495656002ab301ba5a238420b7817aaecbab8e8d156ff2e2",
 "state": "running",
 "time": 111.25
}

After a reviewed abort whose stop was never shown (restore-reviewed): restoration.json
holds the same instance and state, and its time and digest differ, each from a difference
upstream of restore. The script's plane advances its clock by a cut call's float timeout,
0.19999999995343387 s; the tool gives the call its cut as a Duration of whole nanoseconds,
0.2 s. So the abort mark's detail and time differ (164.59999999995335 against
164.5999999999999), the review that names the abort's digest differs, and so do the
restoration's time and reviewed_sha256. The lines differ in the same numbers, in the judge's
parser text for a repeated key (the script prints ValueError('an object repeats a key'),
the tool an object repeats a key), and in the named pipe's refusal, which the tool's case
runs on a plane of its own and so prints apart from the case's lines.

driver.py:

  import importlib.util, shutil, sys, unittest, os, io, contextlib
  from pathlib import Path
  keep = Path(sys.argv[1])
  spec = importlib.util.spec_from_file_location("t", "scripts/test-host-stop-controller.py")
  t = importlib.util.module_from_spec(spec); sys.dont_write_bytecode = True; spec.loader.exec_module(t)
  names = {"test_restore_writes_restoration_once_the_target_runs_with_both_checks_ok": "restore-clean",
           "test_after_an_abort_restore_needs_the_reviewed_record_of_that_abort": "restore-reviewed", "test_a_restoration_reaches_a_stopped_report_dated_after_the_abort_mark": "restore-reaches"}
  class Kept(t.Restore):
      def restore(self, reviewed=None):
          code = super().restore(reviewed)
          if code == 0 and not getattr(self, "kept", False):
              self.kept = True
              name = names[self._testMethodName]
              shutil.copytree(self.evidence, keep / name)
              (keep / f"{name}.lines").write_text(self.output)
          return code
  t.setUpModule()
  suite = unittest.TestSuite([Kept(n) for n in names])
  r = unittest.TextTestRunner(verbosity=1).run(suite)
  sys.exit(0 if r.wasSuccessful() else 1)
